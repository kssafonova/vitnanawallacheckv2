# PORTAL SYSTEMS — правила проекта

Сайт PORTAL SYSTEMS: HS-порталы (подъёмно-раздвижные) и FS-порталы (складные), панорамное остекление, Москва и МО.
Статический сайт на HTML, CSS и JS без сборщика и без зависимостей. Сейчас деплой на GitHub Pages, позже переезд
на REG.RU с PHP (формы уходят через `forms/send.php`).

**Это прототип.** На страницах `noindex`, `robots.txt` закрыт (`Disallow: /`). Оставляем так до запуска —
не открывать индексацию без явной команды владельца. Список дел на запуск будет в `LAUNCH.md`.

## Правила работы

- Каждый этап — отдельный пулл-реквест в `main` с коротким описанием **на русском**.
- После каждого этапа — проверка `node tools/check-site.mjs` (см. ниже). В описании PR — что проверено.
- Сохраняй текущий визуальный стиль: тонкий Manrope (300), крупные заголовки с отрицательным трекингом,
  тонкие линии-разделители, углы без скругления, чёрный `#050505` и бумажный фон `#f7f7f3` / `#ebe8dc`.
- Размеры шрифтов и отступов — **только через токены** из `assets/css/components.css`.
  Жёсткие `px` в `font-size` не использовать. Нужен новый размер — сначала подумай, подходит ли существующий токен;
  если нет — добавь токен в `components.css`, а не число в компонент.
- Текст на экране не мельче 11 px ни на одной ширине. Это касается и подписей внутри SVG: SVG масштабируется,
  поэтому считай итоговый размер (проверка это ловит).
- Manrope подключён локально из `assets/fonts/`. Google Fonts и другие внешние CDN не подключать.
- Не редактируй руками то, что собирает генератор (страницы вариантов, карточки каталога, `sitemap.xml`) —
  правь данные или шаблон генератора и пересобирай.

## Токены (`assets/css/components.css`)

Шкала плавная: `clamp()` от 360 до 1440 px, без скачков на брейкпоинтах.

| Токен | Диапазон | Для чего |
|---|---|---|
| `--fs-label` | 11 → 12 px | КАПС-подписи, eyebrow, кнопки |
| `--fs-caption` | 12 → 13 px | сноски, мелкие пояснения |
| `--fs-small` | 13 → 15 px | описания в карточках |
| `--fs-body` | 15 → 17 px | основной текст |
| `--fs-lead` | 17 → 20 px | лид-абзацы |
| `--fs-h4` | 18 → 22 px | мелкие заголовки, значения |
| `--fs-h3` | 22 → 36 px | заголовки карточек и аккордеонов |
| `--fs-num` | 30 → 52 px | цены, крупные цифры |
| `--fs-h2s` | 32 → 56 px | подзаголовки поверх фото, H1 товара |
| `--fs-h2` | 38 → 84 px | заголовки секций |
| `--fs-h1` | 46 → 112 px | заголовок первого экрана |
| `--fs-display` | 58 → 160 px | акцидентные надписи |
| `--ui-pad` | 20 → 48 px | боковые поля |
| `--space-section` | 64 → 140 px | вертикальный ритм секций |
| `--space-head` | 28 → 56 px | от заголовка секции до контента |
| `--header-h` | 72 / 88 px (с 900 px) | высота шапки, `scroll-margin` якорей |

Цвета: `--ui-black #050505`, `--ui-ink #11110f`, `--ui-paper #ebe8dc`, `--ui-bg #f7f7f3`, `--ui-muted #6f6c64`,
`--ui-line #aaa59a`, `--ui-line-soft #d5d1c7`, `--ui-accent #b1a27a`, `--ui-max 1440px`.

Общие классы там же: `.ui-wrap`, `.ui-eyebrow`, `.ui-title`, `.ui-lead`, `.ui-btn` (`--dark`, `--light`),
`.ui-section-head`, карточка товара `.product-card*` (в т. ч. `--dark`, `--soon`).

## Структура

```
index.html                  главная (калькулятор, системы, проекты, форма)
systems/hs/, systems/fs/    страницы систем HS и FS
catalog/index.html          каталог: карточки по моделям
catalog/hs-portaly/<slug>/  страницы вариантов HS (модель × цвет × схема)
catalog/fs-portaly/<slug>/  страницы вариантов FS (пока «скоро»)
data/products.json          модели, цвета, схемы, цены — источник данных каталога
data/site-config.json       домен и SEO-настройки
assets/css/components.css   токены, шрифты, общие компоненты (подключается во все CSS через @import)
assets/css/site.css         главная и общие секции; catalog.css, product.css, hs-system.css, fs-system.css, calculator.css
assets/js/components/       <site-menu> и <site-footer> — веб-компоненты шапки и подвала (Shadow DOM, атрибут data-base)
assets/js/                  calculator*.js, hs-system.js, product.js, site.js
assets/fonts/               Manrope (woff2, кириллица + латиница), OFL.txt
assets/images/              фото (webp/jpg)
forms/send.php, config.php  отправка заявок на почту (PHP mail) — работает только на REG.RU
canvas/                     черновые интерактивные схемы HS/FS (не часть сайта, в sitemap не входят)
tools/build.mjs             генератор каталога и sitemap из data/products.json
tools/check-site.mjs        проверка сайта в браузере
```

Пути в HTML относительные (`../../`), чтобы сайт работал и на GitHub Pages в подпапке, и на своём домене.
Шапка и подвал получают корень сайта через `data-base`, например `<site-menu data-base="../../"></site-menu>`.
Боевой домен — `https://www.portal-systems.ru/` (канонические адреса, sitemap).

## Генератор каталога (`tools/build.mjs`)

```
node tools/build.mjs          # собрать после любой правки data/products.json или шаблона
node tools/build.mjs --check  # ничего не пишет; код 1, если файлы устарели (запускать перед PR)
```

Источник — `data/products.json`: модели с цветами и схемами, вариант = модель × цвет × схема.
Адрес варианта: `catalog/<cat>/<профиль>-<Ш>x<В>-<цвет.slug>-<схема.slug>/`, артикул
`STD-<модель>-<профиль>-<Ш>X<В>-<RAL>-<код схемы>`. Не меняй `slug` у опубликованных цветов и схем — сменится адрес.

Генератор собирает:
- страницы всех вариантов — цена, цвет, схема, характеристики прямо в HTML; canonical на себя;
  переключатели цвета и схемы — обычные ссылки; JSON-LD `Product`/`Offer` и `BreadcrumbList`;
- блоки между `<!-- build:имя -->` и `<!-- /build:имя -->`: карточки моделей в `catalog/index.html`
  и `systems/hs/index.html`, первый экран HS, мини-карточки на главной. Остальное на этих страницах — ручная вёрстка;
- `sitemap.xml` (главные страницы + все варианты).

Папки `catalog/hs-portaly/` и `catalog/fs-portaly/` принадлежат генератору: лишние удаляются.
`status: "soon"` — страница есть, цена скрыта, в JSON-LD нет `Offer`, в фид не попадает (FS пока так).
`status: "available"` — в продаже.

Фото: одно на модель (`image`). Фото по цветам кладутся в `assets/images/products/<модель>/<цвет.slug>.webp`
(например `hs2/belyi.webp`) и подхватываются при сборке; список недостающих генератор печатает сам.

## Проверка

```
node tools/check-site.mjs                 # все страницы из sitemap.xml на 360, 390, 768, 1280, 1920
node tools/check-site.mjs /catalog/       # отдельные страницы
node tools/check-site.mjs --shots .check  # плюс скриншоты во всю страницу (папка .check в .gitignore)
```

Скрипт поднимает свой локальный сервер и открывает страницы в Chromium через Playwright.
Проверяет: ошибки в консоли и 404 локальных файлов, горизонтальную прокрутку, текст мельче 11 px
(включая подписи в SVG с учётом масштаба). Код выхода 1 — есть нарушения. Скриншоты смотри глазами:
скрипт не видит наложений и сломанной вёрстки.

## Дорожная карта

1. `CLAUDE.md` — этот файл.
2. Каталог из `data/products.json`: генератор статических страниц 16 вариантов (8 HS, 8 FS), карточки каталога
   по моделям, JSON-LD Product/Offer, `sitemap.xml`. FS — статус «скоро»: страницы есть, в фид не попадают.
3. YML-фид для Яндекс Товаров (`feed.yml`) — тем же генератором; данные совпадают со страницами.
4. Корзина и оформление заказа без онлайн-оплаты. **Перед началом этапа 4 спросить владельца.**
5. Обязательные страницы: «Реквизиты / О компании», «Доставка и монтаж», «Оплата», «Возврат»
   (реквизиты — заглушки `[ЗАПОЛНИТЬ]`).
6. `LAUNCH.md` — список дел на запуск.

После этапов 2–5 **предложить, но не делать без согласия**: перестройку мобильной страницы HS
(12 экранов → ~7) и два действия на всём сайте: «Выбрать готовый портал» и «Рассчитать под свой проём».

## Известные проблемы

- PDF политики конфиденциальности (`content/privacy-policy-portal-systems.pdf`) отсутствует — ссылка в формах битая.
- `index.html` и `systems/*` помечены `index,follow`, остальные — `noindex`; до запуска всё закрыто `robots.txt`.
- Почта в `forms/config.php` не заполнена.
- Справочные цены калькулятора HS заданы в `assets/js/hs-system.js` (`refs`) отдельно от каталога —
  генератор предупреждает, если они разошлись с `products.json`. Интерактивная схема на странице HS
  показывает вариант HS / 36 «2 активные справа», которого нет в каталоге.
