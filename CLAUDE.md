# PORTAL SYSTEMS — правила проекта

Сайт PORTAL SYSTEMS: HS-порталы (подъёмно-раздвижные) и FS-порталы (складные), панорамное остекление, Москва и МО.
Статический сайт на HTML, CSS и JS без сборщика и без зависимостей. Сейчас деплой на GitHub Pages, позже переезд
на REG.RU с PHP (формы уходят через `forms/send.php`).

**Это прототип.** На страницах `noindex`, `robots.txt` закрыт (`Disallow: /`). Оставляем так до запуска —
не открывать индексацию без явной команды владельца. Список дел на запуск будет в `LAUNCH.md`.

## Правила работы

- Каждый этап — отдельный пулл-реквест в `main` с коротким описанием **на русском**.
- После каждого этапа — проверка `node tools/check-site.mjs` (см. ниже). В описании PR — что проверено.
- Сохраняй текущий визуальный стиль: тонкий Manrope (300), крупные заголовки с отрицательным трекингом,
  тонкие линии-разделители, углы без скругления, чёрный `#050505` и нейтральный светлый фон `#f5f5f4` / `#ededeb`.
  Бежевые и желтоватые фоны не использовать (решение владельца) — только нейтральные серые.
- **Плоско, как инженерный чертёж** (решение владельца): схемы, подбор, калькулятор, формы, списки и таблицы — тонкие
  линии на белом/светлом фоне, без теней и «объёмных» плиток. Тень и подъём при наведении — только у карточек товаров
  `.m-card` (и финальной плашки «Показать» в подборе HS). Не превращать страницы в «белые карточки с тенью».
  Выбранный вариант — чёрная заливка, без радиокнопок и галочек; где можно выбрать несколько — «+» / «✓».
- Размеры шрифтов и отступов — **только через токены** из `assets/css/components.css`.
  Жёсткие `px` в `font-size` не использовать. Нужен новый размер — сначала подумай, подходит ли существующий токен;
  если нет — добавь токен в `components.css`, а не число в компонент.
- Текст на экране не мельче 11 px ни на одной ширине. Это касается и подписей внутри SVG: SVG масштабируется,
  поэтому считай итоговый размер (проверка это ловит).
- Manrope подключён локально из `assets/fonts/`. Google Fonts и другие внешние CDN не подключать.
- Не редактируй руками то, что собирает генератор (страницы вариантов, карточки каталога, `sitemap.xml`) —
  правь данные или шаблон генератора и пересобирай.

Хлебные крошки — на всех страницах, кроме главной: `<nav class="crumbs"><div class="ui-wrap crumbs__in">…</div></nav>`
(стили в конце components.css, разделитель «—», текущая страница — `<span aria-current="page">`). Поверх фото первого экрана
(о компании, HS, FS) — `.crumbs--over`. На странице товара крошки собирает генератор. Новая страница — сразу с крошками.

Пути в HTML относительные (`../../`), чтобы сайт работал и на GitHub Pages в подпапке, и на своём домене.
Шапка и подвал получают корень сайта через `data-base`, например `<site-menu data-base="../../"></site-menu>`.
Боевой домен — `https://www.portal-systems.ru/` (канонические адреса, sitemap).

## Генератор каталога (`tools/build.mjs`)

```
node tools/build.mjs          # собрать после любой правки data/products.json или шаблона
node tools/build.mjs --check  # ничего не пишет; код 1, если файлы устарели (запускать перед PR)
```

Источник — `data/products.json`: модели с размерами, цветами и схемами, вариант = модель × размер × цвет × схема.
**Размеры — по таблице владельца** (поле `sizes`: `width`, `price`, `passage` — чистый проход, `note`):
HS2 (2 секции, 1 активная / 1 глухая, рама 158) — 3,0 / 3,6 / 4,0 / 5,0 м, схемы «слева» (A-L) / «справа» (A-R);
HS3 (3 секции, 2 активные / 1 глухая, рама 246) — 4,5 / 5,4 / 6,0 м, «налево» (D-L, каскадом влево) / «направо» (D-R);
HS4 (4 секции, 2 активные / 2 глухие, рама 158) — 4,8 / 6,0 / 7,2 / 8,0 м, «из центра» (F-Center). Высота `heights` — 2300/2400 мм, цена одна.
Ширина створки = ширина / секции. Цена и чистый проход не хранятся — их считает `portal-calc.js` по ТЗ калькулятора. `default_width` — размер, выбранный в карточке (3,6 / 5,4 / 6,0 м).
Код варианта — `code_prefix/ширина в дм` (HS2/36, HS3/54, HS4/60), название — `name_base` + ширина («Раздвижная портальная дверь 3,6 м»),
`schemes[].how` — «как работает» (страница товара, подбор HS).
Адрес варианта: `catalog/<cat>/<профиль>-<Ш>x<В>-<цвет.slug>-<схема.slug>/` (В — первая высота, 2300), артикул
`STD-<модель>-<профиль>-<Ш>X<В>-<RAL>-<код схемы>`. Не меняй `slug` у опубликованных цветов и схем — сменится адрес.

Генератор собирает:
- страницы всех вариантов — цена, цвет, схема, характеристики прямо в HTML; canonical на себя;
  переключатели цвета и схемы — обычные ссылки; JSON-LD `Product`/`Offer` и `BreadcrumbList`;
- блоки между `<!-- build:имя -->` и `<!-- /build:имя -->`: карточки моделей в `catalog/index.html`
  и `systems/hs/index.html`, первый экран HS, мини-карточки на главной. Остальное на этих страницах — ручная вёрстка;
- `sitemap.xml` (главные страницы + все варианты);
- `data/catalog.json` — артикулы, цены и названия для корзины.

Карточки товаров — компонент `.m-card` в `components.css`, по макету владельца: 3D-превью → серым «3600 × 2300/2400 мм · 2 секции» →
название «Раздвижная портальная дверь 3,6 м» → «Проём:» (ширины модели кнопками 3,0 / 3,6 / …) → «Схема:» → «Цвет:» (квадраты + «любой RAL»)
→ линия → цена и «за конструкцию» → «В корзину +» во всю ширину. Подписи над выбором. Проём меняет название, размер, цену, артикул
и ширину 3D-модели (`data-sizes`, shop.js, card3d.js). Названия цвета и схемы в тексте карточки не дублировать. Карточки широкие
(решение владельца, «как нормальная карточка в магазине»): сетка 1 в ряд на телефоне, 2 с 640 px, 3 с 1100 px; фото 4:3
(`--m-ar`), фон под моделью белый; рядом с цветами «+ любой RAL»; первым идёт тёмный цвет (у HS/30 белый — второй); цена справа от кнопки, над ними тонкая линия. В каталоге (`/catalog/`) есть переключатель вида (`assets/js/catalog-view.js`, `main[data-view]`, стили в catalog.css): «Крупные карточки» (по умолчанию) — 1 в ряд на телефоне, 2 × 2 с 640 px; «Плитка» — 2 × 2 на телефоне, 3 с 768 px, 4 с 1100 px. «Индивидуальный расчёт» в каталоге — обычная четвёртая карточка. Выбор запоминается в localStorage. Раскладка внутри карточки — по её ширине (container query): до 340 px подписи над выбором и цена над кнопкой, уже 260 px — компактная. Последняя
карточка HS — «Индивидуальный расчёт» (`.m-card--wide`), вся карточка — ссылка на `/raschet/`; с 1100 px это баннер
во всю ширину ряда под тремя моделями.
Превью в карточке — 3D-модель (`card3d.js`): генератор кладёт в `data-3d` размер, створки, куда они едут, ручки,
цвета RAL и зеркальность схем (`LAYOUT_3D` / `model3d` в build.mjs). Один WebGL-рендерер на все карточки, кадр — только
по изменению. Потянуть — повернуть, наведение (на телефоне кнопка «Открыть») — створки открываются по схеме,
свотчи меняют цвет и схему (событие `ps-card-variant` из shop.js). Нет WebGL или JS — остаётся фото.

### Калькулятор и заявки — единые правила
- Калькулятор один — страница `/raschet/` (блок `build:raschet-calc`, `assets/js/quick-calc.js`), **логика — по ТЗ владельца**
  («Онлайн-калькулятор портальных систем»). Все правила — в `assets/js/portal-calc.js` (`window.PSPortal`); этим же файлом
  генератор считает цены и проходы готовых дверей каталога (через `node:vm`), так что каталог и калькулятор не расходятся.
  - Тип: HS (раздвижная, усиленный термопрофиль) или FS (гармошка). Лимиты: HS — высота 1800–3700, ширина 1500–19800 мм;
    FS — 1800–2800 и 1500–12000 мм. Проверка при выходе из поля: ошибки и плашки (створка HS > 8,5 м² — спецтехника и стекло от 8 мм;
    FS выше 2,4 м — элементы жёсткости; FS шире 12 м — «используйте подъёмно-сдвижную»).
  - Секции по ширине и «Рекомендуем»: HS < 4 м — 2; 4–6 — 2/3 (рек. 3); 6–8 — 3/4 (рек. 4); 8–12 — 4/6 (рек. 6); > 12 — 6.
    FS: < 2,5 — 2/3; 2,5–4 — 3/4; 4–6 — 5/6; 6–7,5 — 6/7; 7,5–12 — 7/8 (рекомендуется большее). Плюс число створок готовой двери этой
    ширины (HS4/48 из таблицы размеров по ТЗ не попадает — оставлено как исключение для каталога).
  - Проход: HS 2 секции — w/2 − 150; 3 каскадом — w/3·2 − 200; схема G — w/3 − 120; 4 — w/2 − 250; 6 — w/6·4 − 300; FS — w − n·95 − 120.
  - Схемы: HS A-L, A-R (2), D-L, D-R каскад и G (3), F-Center (4), C-Double (6); каскад (D-L, D-R, C-Double) — рама 246 мм, иначе 158.
    FS — влево / вправо / в две стороны (чётное число), «Активная рабочая дверь» — для 3, 5, 7 секций. Эскизы со стрелками — `layout()`,
    чертёж — `opening-draw.js` (FIX / ACTIVE / FOLD / DOOR).
  - Цена: S × 55 000 ₽/м² (HS) или 40 000 (FS) → ×1,4 за каскад → ×1,05 двухсторонняя покраска (Color-Bi) → стекло SP-Solar ×1,06,
    SP-Triplex ×1,125 (триплекс обязателен, если створка > 5 м²) → +18 000 ₽ ручка с замком (Control-Lock). Однотонный RAL — любой, без наценки.
  - Итог: чертёж, резюме (материал, механизм, закалка, чистый проход), цена крупно, дисклеймер про доставку, монтаж и порог,
    `<lead-form>` с кнопкой «Получить точную смету проекта в PDF» (параметры уходят в письмо, `setProject`).
  - **Размер — только поля «Ширина» / «Высота»** (решение владельца: без кнопок готовых размеров). Цена всегда по формуле.
    Если размер и выбранная конфигурация совпали с дверью каталога (`data-doors` из `calcReady`: HS, ширина и створки, высота 2300 или 2400,

## Корзина

- `assets/js/shop.js` — корзина в `localStorage` (`ps-cart`: `[{sku, qty}]`), кнопки `[data-add-to-cart]`,
  переключение цвета и схемы в карточках. Подключать на страницах с карточками и кнопками «В корзину».
- Счётчик в шапке — в `<site-menu>`, слушает событие `ps-cart-change`.
- `/cart/` — список, количество, итог, оформление (имя, телефон, город, комментарий, согласие); `assets/js/cart.js`.
  Цены берутся из `data/catalog.json`, не из хранилища. Заказ → `forms/send.php` с `source=cart`
  (номер `PS-ГГММДД-XXXX`, письмо «Заказ № …») → `/cart/done/?order=…`.
- **Цены без «от»** (требование Яндекс Товаров): у товаров, в корзине, письме и на «Заказ принят» — просто сумма;
  доставка и монтаж — оценка, пишем «≈ 45 000 ₽».
- Пустая корзина: без шапки «Корзина» и шагов после заказа — «Корзина пуста», кнопки в каталог и калькулятор и лента
  «Готовые конструкции» (карточки `.m-card`, блок `build:cart-recs` собирает генератор). Шапка «Корзина N» и шаги — только когда есть товары.
- Онлайн-оплаты нет: звонок инженера → замер → договор → счёт.
- Срок изготовления — `services.production_days_min` / `production_days_max` в `data/site-config.json` (сейчас 30–60 дней,
  решение владельца): на странице товара у цены («Срок — 30–60 дней»), в корзине у каждого товара и в итоге. Корзина показывает
  окно доставки / самовывоза «27 октября — 26 ноября» = сегодня + 30…60 дней, с пометкой, что точный день согласует менеджер;
  окно уходит и в письмо заказа. Срок продублирован вручную в FAQ (главная, HS), «О компании» и линиях времени — меняйте вместе.
- Получение: «Доставка и монтаж» — оценка `services.install_delivery_pct` % от стоимости конструкций, не меньше
  `install_delivery_min` (сейчас 12 %, от 45 000 ₽, Москва и МО до 50 км от МКАД), или «Самовывоз с производства» (0 ₽,
  город не нужен). Значения — в `data/site-config.json`, в корзину попадают через `data/catalog.json` (пересобрать).
- На GitHub Pages PHP не работает, поэтому оформление там показывает ошибку отправки. Полностью работает на REG.RU.

Производство и самовывоз: Москва, ТиНАО, Краснопахорский район, квартал № 205, 1, стр. 1; ежедневно 10:00–20:00
(по данным Яндекс Карт); координаты 55.404982, 37.402583; организация на Яндексе — https://yandex.ru/maps/org/okna/178905094330/.
Карта на `/contacts/` грузится только по нажатию «Показать карту» (виджет Яндекса), до этого — никаких сторонних запросов.
Адрес и телефон продублированы вручную в `about/`, `contacts/`, подвале и `site-config.json` — меняйте везде.

Папки `catalog/hs-portaly/` и `catalog/fs-portaly/` принадлежат генератору: лишние удаляются.
`status: "soon"` — страница есть, цена скрыта, в JSON-LD нет `Offer`, в фид не попадает (FS пока так).
`status: "available"` — в продаже.

Фото вариантов: `assets/images/products/<модель>/<цвет.slug>-<схема.slug>.webp` и `…-open.webp` (открытый вид,
тот же ракурс). Их делает `node tools/recolor-photos.mjs` из студийного рендера модели (поле `render` в
`products.json`: закрытый и открытый кадр и схема на нём): перекрашивает раму в RAL каждого цвета, зеркальные
схемы отражает. Потом `node tools/build.mjs`. Нет фото варианта — стоит общее фото модели (`image`);
список недостающих генератор печатает сам. На странице товара — переключатель «Закрыто / Открыто»,
в карточке открытый вид показывается при наведении. Рендеры: HS / 30, HS / 36 — закрыто + открыто,
HS / 48 — закрыто + открыто (ручки на рендерах разного цвета), FS / 36 — только закрыто (открытый кадр
не соответствует схеме 3 + 1), FS / 27 — нет рендера.
Параметры `render`: `flip` — рендер зеркален схеме (HS / 36: активные створки на рендере справа, в D1 — слева);
`align` — открытый кадр снят с другой точки, скрипт выравнивает его по четырём углам рамы закрытого.
Горизонтальные кадры дополняются фоном до 4:5, чтобы рама не обрезалась в квадратной карточке.
Проверяй схему по кадру: где ручка и куда складывается пакет — открытый кадр должен совпадать со схемой SKU.

## Известные проблемы

- FS в каталоге (схемы 330 и 431 «3 + 1») не совпадают со схемами FS из ТЗ калькулятора — пересобрать, когда FS пойдёт в продажу.
- PDF политики конфиденциальности (`content/privacy-policy-portal-systems.pdf`) отсутствует — ссылка в формах битая.
- `index.html` и `systems/*` помечены `index,follow`, остальные — `noindex`; до запуска всё закрыто `robots.txt`.
- Почта в `forms/config.php` не заполнена.
- `forms/send.php` принимает файл проекта (`project_file`: PDF, DWG, DXF, JPG, PNG, WEBP, HEIC, ZIP до 15 МБ) и шлёт его вложением.
  На REG.RU проверить `upload_max_filesize` ≥ 16M и `post_max_size` ≥ 20M, иначе большие файлы не дойдут.
- Скрытый прежний калькулятор главной (`calculator.js`) считает антрацит на 4 % дороже белого; каталог и `/raschet/` — по одной цене.
- Фото в блоках «Стеклопакеты» и «Как работает» на странице HS (`assets/images/systems/hs-glass-44.webp`,
  `hs-mechanism.webp`, `hs-steps/`) вырезаны из макетов и увеличены — заменить исходными рендерами без подписей
  (ширина от 1600 px, шаги от 400 px), имена файлов оставить.
- Справочные цены калькулятора HS заданы в `assets/js/hs-system.js` (`refs`) отдельно от каталога —
  генератор предупреждает, если они разошлись с `products.json`. Конфигуратор «Как открывается дверь»
  (`hs-opening.js`) берёт размеры из генератора (блок `build:hsx-data`): створки → ширина → схема, проход из таблицы.
